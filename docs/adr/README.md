# Architecture Decision Records

Use ADRs for decisions that materially affect architecture, security boundaries, public APIs, data models, deployment, or smart-contract behavior.

## Format

Each ADR should contain:

- Status
- Context
- Decision
- Alternatives considered
- Consequences
- Security implications
- Follow-up work

Name records sequentially, for example `0001-record-architecture-decision.md`.

## Current records

No formal ADRs existed before the repository foundation work. The existing implementation is documented in `docs/ARCHITECTURE.md`; future architectural changes should add an ADR rather than relying on chat history or undocumented convention.
