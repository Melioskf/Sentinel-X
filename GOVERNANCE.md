# Governance

SentinelX is currently maintained by the repository owner and follows a maintainer-led model.

## Decision process

1. Document the problem and proposed change in an issue or PR when the work is non-trivial.
2. Prefer evidence from tests, threat analysis, operational constraints, and user impact.
3. Security-sensitive changes require explicit security consideration before merge.
4. The maintainer makes the final merge and release decision.

## Changes to project direction

Major architectural, protocol, authentication, transaction-policy, or smart-contract changes should be documented in an ADR under `docs/adr/`.

## Releases

Releases should be accompanied by a changelog entry and, when behavior or deployment changes, updated documentation. See `docs/WORKFLOW.md` and `CHANGELOG.md`.
